## 3. P0-2 判据校准（审计过程发现，【适配】标注）

首轮全量扫描在 smoke 档 `feedback_match` tag 命中 6 条 prompt 故障名。
溯源 `src/sandbox/policy.py:_feedback_addresses`：该调用是**沙盒环境侧**
匹配器，prompt 中的"执行环境注入的故障规格"来自环境自身注入（等价于真实
执行器知道自己的报错），铁律保护对象是判官/归因器，不限制执行环境——
代码内已有明文论证。判据据此精确化为：判官类 tag 零容忍（硬门槛），
`feedback_match` 单列环境侧来源。其余 7 档判官 tag 全部 0 命中。
`realtest_audit.py` 已实现该区分。

## 4. binary_search 3/18 未达标·归因分析（判官能力 vs 管线缺陷）

管线机制正确（FakeLLM 同配置 15/18）；偏差是真实判官在"前半段重放是否

realtest_deepseek 在 demo 上 2/6 的历史方向一致，与 Who&When 文献
"二分弱于单遍"一致。**处置建议：主定位用 all_at_once（本次 corpus 上
16/18）/chief（17/18），binary_search 降级为辅助精修或提高判官温度
预算再评估，不构成上线阻塞。**

## 6. 事件与处置记录

1. **⑦ 首跑崩溃（8192）**：mast_judge 单条思考链随机爆炸吃满 8192 → content
   空，修复重试 3 次仍空 → `structured parsing still failing` 退出 1。同语料
   同算法在 v3/v4 可通过，判定为随机思考爆炸而非管线缺陷。处置：该档
   `max_completion_tokens: 16384`，整档重跑，mast_judge 18/18 全过。
2. **402 余额耗尽**：重跑至 all_at_once（45 条记录）时账户余额不足，外部
   阻塞。续跑命令（充值后 ~10 分钟收尾）：
   ```bash
   OPENAI_API_KEY=<key> OPENAI_BASE_URL=https://api.deepseek.com \
     .venv/bin/atap run --config configs/final_smoke_corpus.yaml --out runs/final/final-smoke-corpus
   .venv/bin/python docs/realtest_audit.py runs/final/final-smoke-corpus
   ```
